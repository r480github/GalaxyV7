CSS Grid Layout

Stop arranging.
Start placing.

Flexbox lays out items along one line and lets their content push them around. Grid does the opposite: you draw a two‑dimensional structure first, then drop items into it. Here is every property, every value, and a live demo for each.

Flexbox — content first

One axis at a time. You give items a direction and rules for how leftover space is shared; the items' own sizes drive the result. Great for a toolbar, a row of tags, a centered thing.

Grid — layout first

Two axes at once. You define columns and rows up front — a real coordinate system — and assign items to specific lines or areas. Great for page layouts, cards, dashboards, any 2D arrangement.

Two vocabularies run through everything below. Blue is always structure — the container, its lines and tracks. Coral (and friends) are always the items you place into it.

Defining the grid · the container

Turning on the grid

Everything starts on the container. The moment you declare a display value, its direct children become grid items — and their own float, clear, and vertical-align stop mattering.

display

Two values create a grid. grid makes the container a block (it takes the full width available). inline-grid makes it flow inline with surrounding text, sized to its contents — exactly the block/inline distinction you know from flex.

  • display: grid — block-level grid container
  • display: inline-grid — inline-level grid container
Coming from flex: an empty grid container does nothing visible. Unlike flex, items don't auto‑arrange into a usable layout until you also define tracks (next). A bare display:grid just stacks everything into one column.

Defining the grid · the container

Drawing the tracks

grid-template-columns

The single most important property. You list the size of each column, separated by spaces. The number of values = the number of columns. Sizes can be lengths (px, rem, %), the auto keyword, the flexible fr unit, or functions like minmax(). Click to rebuild the grid:

grid-template-rows

Identical syntax, vertical axis. You often don't set this — rows that you didn't define are created automatically and sized by their content (that's the implicit grid, covered later). Define rows explicitly when you need fixed heights, like a header/body/footer column.

  display: grid;
  grid-template-rows: 60px 1fr 40px;
}

Defining the grid · the container

Naming regions

grid-template-areas

Instead of counting line numbers, you can paint an ASCII map of your layout. Each quoted string is a row; each word is a named cell. Repeat a name to make an item span. An item then claims its region with grid-area: name. Use a dot . for an empty cell.

a classic holy-grail layout, by name
head
side
main
foot
.page {
  display: grid;
  grid-template-columns: 140px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "head head"
    "side main"
    "foot foot";
}
header { grid-area: head; }
main   { grid-area: main; }
Why it's loved: the source order of your items no longer matters, and you can completely re‑flow the layout at a breakpoint just by rewriting the area map — no other rules change. Each row string must have the same number of columns, and every named area must form a solid rectangle.

Defining the grid · the container

The template shorthand

grid-template shorthand

Combines grid-template-rows, grid-template-columns, and grid-template-areas in one declaration. Rows and their area strings interleave; columns come after a slash. Powerful but dense — most people keep the three longhands for readability.

.page {
  grid-template:
    "head head" 50px
    "side main" 1fr
    "foot foot" 40px
    / 140px  1fr;   /* the column track list */
}

Sizing toolkit · track values

Flexible space: the fr unit

The fr unit is grid's headline feature and the closest thing to flex-grow. One fr = one share of the leftover space after fixed sizes and gaps are subtracted. 2fr takes twice the share of 1fr.

watch the shares redistribute
1fr
1fr
1fr
columns: 
#grid { grid-template-columns: 1fr 1fr 1fr; }
/* 200px 1fr 2fr → fix 200px first, then split the rest 1:2 */
Subtle but important: by default an fr track won't shrink below the size of its content (its minimum is auto, i.e. min-content). If long words or images are blowing out your tracks, swap 1fr for minmax(0, 1fr) — that's the single most common grid gotcha.

Sizing toolkit · track values

Content-based sizes

Beyond lengths and fr, tracks can size themselves to what's inside them.

  • auto — grows to fit content; in alignment terms it behaves like max-content for a max but can stretch to fill leftover space. The everyday "as big as it needs to be" value.
  • min-content — the smallest the content can get without overflowing (roughly the longest unbreakable word).
  • max-content — the size content would take if it never wrapped (the whole string on one line).
  • fit-content(limit) — acts like auto but never grows past limit. e.g. fit-content(300px): shrink‑to‑fit, capped at 300px.
min-content · max-content · fit-content(220px) · 1fr
min-content wraps hard
max-content stays on one line
fit-content caps the width once it reaches the limit you set
1fr
.grid {
  grid-template-columns:
    min-content max-content fit-content(220px) 1fr;
}

Sizing toolkit · functions

Ranges with minmax()

minmax(min, max)

Defines a track that's clamped between a floor and a ceiling. The track will be as large as max allows but never smaller than min. minmax(150px, 1fr) reads: "at least 150px, but grow to take a fair share of free space." This is the backbone of responsive grids.

grid-template-columns: minmax(120px, 250px) 1fr
≥120, ≤250
1fr fills the remainder
.sidebar-layout {
  grid-template-columns: minmax(120px, 250px) 1fr;
  /* sidebar flexes within a range, content takes the rest */
}

Sizing toolkit · functions

Repeating tracks

repeat(count, tracks)

Shorthand for repetitive track lists. repeat(12, 1fr) builds a 12‑column grid. The pattern can be multiple tracks — repeat(3, 1fr 2fr) yields six columns (1fr 2fr 1fr 2fr 1fr 2fr). You can also mix it with explicit tracks on either side.

Sizing toolkit · functions

Responsive grids with no media queries

auto-fill  vs  auto-fit

Pass auto-fill or auto-fit as repeat()'s count and the browser fits as many tracks as will fit on the row, reflowing on its own as the container resizes. Combined with minmax(), this replaces most flex-wrap card layouts. The two keywords differ only when there are fewer items than fit:

  • auto-fill — keeps the empty tracks. Leftover space stays as blank columns.
  • auto-fit — collapses empty tracks to zero, so the existing items stretch to fill the row.
auto-fill — empties preserved
1
2
3
auto-fit — items stretch
1
2
3
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 1rem;
  /* as many ≥220px columns as fit; they stretch to fill. Resize me! */
}
The pattern to memorize: repeat(auto-fit, minmax(MIN, 1fr)). It's the responsive card grid in one line. Use auto-fill instead if you want the column rhythm to stay even when only a couple of items are present.

Sizing toolkit · naming

Naming the lines

You can name grid lines by putting identifiers in square brackets within the template. Items then reference those names instead of numbers, which survives refactors far better. A single line can carry multiple names.

.grid {
  grid-template-columns:
    [full-start] 1rem [content-start] 1fr [content-end] 1rem [full-end];
}
.hero { grid-column: full-start / full-end; }
.text { grid-column: content-start / content-end; }
Bonus: when you name an area with grid-template-areas, you automatically get line names for free — an area called main creates lines main-start and main-end on both axes.

The gutters

Spacing between tracks

gap · row-gap · column-gap

Gaps add space between tracks only — never on the outer edges (use padding for that). gap is shorthand: one value sets both axes; two values are row-gap column-gap. Drag the value:

Coming from flex: gap was born in Grid but now works in flexbox too — so you can finally delete those margin-right hacks. The old names grid-gap, grid-row-gap, and grid-column-gap still work but are deprecated aliases of the unprefixed versions.

The implicit grid

Tracks you didn't ask for

When you place more items than your defined (explicit) tracks hold, grid generates extra (implicit) tracks to catch them. These properties control how big those auto‑created tracks are.

grid-auto-rows · grid-auto-columns

Default implicit tracks are sized auto (content height). Set grid-auto-rows to give every overflow row a consistent size — useful when you only defined columns and let rows generate themselves.

2 columns defined; rows auto-generate at 70px each

The implicit grid

The auto-placement algorithm

grid-auto-flow

Controls how items that you haven't explicitly placed get slotted in. row (default) fills left‑to‑right then down; column fills top‑to‑bottom then across. Adding dense lets the algorithm backfill earlier holes left by larger items — visually tighter, but it can reorder items away from source order.

item 1 spans 2 cols — watch where the rest land

Accessibility note: dense (and order, later) changes only the visual position. Screen readers, tab order, and copy‑paste still follow the DOM order — so don't use it to fix meaningful reading order.

Alignment · all items at once

Aligning items inside their cells

These four control how every item sits within its own cell. justify-* is the inline (row / horizontal) axis; align-* is the block (column / vertical) axis. This is the opposite mapping from how you might think of flex, so it's worth burning in: justify = across, align = down.

justify-items

Positions items along the row axis inside each cell: stretch (default — fill the cell width), start, end, center.

place-items shorthand

One line for both: place-items: <align-items> <justify-items>. A single value applies to both axes — so place-items: center is the famous, complete way to perfectly center children both ways.

.center-everything {
  display: grid;
  place-items: center;   /* dead-center, both axes, done */
}

Alignment · the whole grid

Aligning the grid within the container

When the tracks together are smaller than the container, these decide what happens to the leftover space — they move the whole grid, not the items within cells. (If your tracks already fill the container, e.g. with fr, these do nothing.)

justify-content

Distributes extra space on the row axis: start, end, center, space-between, space-around, space-evenly — the same value set as flexbox.

place-content shorthand

place-content: <align-content> <justify-content>. place-content: center parks the entire grid in the middle of an oversized container.

The mental model: *-items / *-self move items inside their cells. *-content moves the grid as a whole inside the container. Different jobs, similar names.

Placing items · the item

Placing one item by line

Everything so far lived on the container. These live on individual items and let you pin them to exact grid lines — and span across tracks.

grid-column-start / -end · grid-row-start / -end

Name the line where an item begins and ends. Lines count from 1 on the left/top; negative numbers count from the end (-1 is the last line). The space between is what the item occupies.

grid-column · grid-row shorthand

The shorthands: grid-column: start / end. Use the span keyword to count tracks instead of naming an end line — grid-column: 1 / span 2 starts at line 1 and covers two columns. Click an option for the coral item:

Placing items · the item

Placing by area

grid-area

Two jobs in one property. Named form: grid-area: main drops the item into a region you defined with grid-template-areas. Numeric form: a four‑value super‑shorthand for all four lines at once, in the order row-start / column-start / row-end / column-end.

grid-area: 1 / 2 / 3 / 4  (rows 1→3, cols 2→4)
·
1 / 2 / 3 / 4
·
/* named — pairs with grid-template-areas */
.hero { grid-area: hero; }

/* numeric — row-start / col-start / row-end / col-end */
.feature { grid-area: 1 / 2 / 3 / 4; }
Watch the order. grid-area's numeric order (row / col / row / col) is not the same as reading grid-column then grid-row. When in doubt, the two‑property form (grid-column + grid-row) is harder to get wrong.

Placing items · the item

Aligning a single item

The per‑item counterparts to justify-items / align-items. Set them on one item to override the container's alignment just for that item.

Placing items · the item

Order, overlap & layering

order

Just like in flexbox, order (default 0) changes the visual sequence of auto‑placed items — lower numbers first. Same accessibility caveat as dense: it doesn't move the item in the DOM.

Overlapping items + z-index grid superpower

Unlike flex, two grid items can occupy the same cell — just place them on overlapping lines. They stack in source order, and z-index controls which sits on top. This makes captions‑over‑images and layered hero sections trivial, with no absolute positioning.

both items placed in 1 / 1 / 2 / 3; z-index decides the top
background layer
caption on top (z-index: 2)
.photo, .caption { grid-area: 1 / 1 / 2 / 3; } /* same cell */
.caption { align-self: end; z-index: 2; }

Advanced

The grid mega-shorthand

grid shorthand

The most compressed property — it sets the explicit grid (grid-template-rows/columns/areas) and the implicit-grid defaults (grid-auto-rows/columns/flow) at once, resetting any you omit. A leading auto-flow keyword switches the auto‑flow direction. Genuinely useful for defining auto‑flowing tracks compactly, but it's the property most people read least fluently — reach for the longhands unless you have a reason.

/* explicit rows / explicit columns */
.a { grid: 100px 1fr / repeat(3, 1fr); }

/* auto-flowing columns 80px wide, with two fixed rows */
.b { grid: auto-flow 80px / repeat(2, 1fr); }

Advanced · CSS Grid Level 2

Inheriting tracks with subgrid

subgrid

Normally a nested grid has its own independent tracks, so children of different cards never line up. Set a nested grid's grid-template-columns (or rows) to subgrid and it adopts the parent's track lines instead of creating new ones — so content inside separate children aligns to the same master grid. It's the long‑awaited fix for "ragged card internals."

  display: grid;
  grid-row: 1 / 4;
  grid-template-rows: subgrid;  /* share the parent's rows */
}
Support: subgrid is in all current major browsers, but verify your baseline if you must support older versions — it's the newest piece of the spec here.

Advanced · experimental

Masonry layout

Pinterest‑style masonry (columns of unequal, tightly‑packed heights) is being added to Grid via grid-template-rows: masonry (syntax is still being finalized and standardized). It is experimental with limited, flagged support today. If you need masonry in production right now, use a JS library or a CSS columns approach — but it's worth knowing it's coming to native Grid.

/* experimental — not production-ready, syntax may change */
.masonry {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  grid-template-rows: masonry;
}

When to still reach for flexbox: one‑dimensional rows or columns where content sizes should drive the layout — navigation bars, button groups, tag lists, a single centered element, anything that should wrap based on its own content.
